# Worked retention examples

- “Remember verbatim: call me Najjaśniejszy Panie.” Retain the exact wording in
  source quote/detail, kind preference, user scope identity and user-stated
  evidence. Read the topic first. Use the receipt, not an unverified promise.
- “What is 2 + 2?” Answer 4. No durable memory write or folder preparation.
- “TLS failed with error X on machine A, app version B; switching certificate C
  fixed the rerun.” Retain an episode with environment/version, action, observed
  result and bounded evidence. Classify a user report as user-stated; direct tool
  output can support observed evidence. Do not infer that TLS is universally unsupported.
- “We accepted PostgreSQL because of existing operational expertise.” Reuse correct wiki knowledge; otherwise store the
  accepted decision and rationale, then index its stable document ID. A tentative assistant proposal is not an accepted decision.
- “Actually the preference changed.” Recall current key and index revision,
  correct with a guarded operation linking the previous claim revision; retain
  evidence history. Different-machine constraints can coexist without correction.
- “Summarize what we learned.” Read and reflect without writing. If the user has
  authorized durable consolidation and the conclusion is supported, dry-run a
  small explicit plan with pinned source/target revisions, then apply and inspect
  applied/pending steps. A changed source makes the derived summary stale; do not
  regenerate automatically or pretend a partial operation completed.
- “Remember this” using read-only access: explain the missing write capability.
  Do not copy private memory into another vault, local folder or external service.
